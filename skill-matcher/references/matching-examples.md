# 匹配样例集（打分与决策实测）

本文件既是**打分参考**，也是**回归测试用例集**。每条用例给出：用户输入 → 预期档位 → 预期动作 → 预期输出。

技能清单以会话上下文中注入的可用技能为准；下列示例基于作者本机的技能集（browser-use、clarify-before-action、codex-desktop-download、frontend-design、h3-prompt-writing、minimax-docx、pdf、script-to-manhua-drama、smart-charts、tencent-news、web-access、xlsx、yt-dlp、aihot，以及内置的 tencent-docx / tencent-pptx / tencent-docs-sheet-* / doc-formatter 等）。

---

## A. 直接调用（唯一高置信度）

### A1
- **输入**：「把这份 quarterly.pdf 拆成每页一个文件」
- **候选**：`pdf`（高）
- **理由**：任务核心动作是 PDF 拆分，正是该技能覆盖的操作。
- **动作**：直接调用
- **输出**：`用 pdf 处理：PDF 拆分是它的直接能力。`

### A2（反例：看似唯一，实为双候选）
- **输入**：「这张图里的表格提出来存成 Excel」
- **候选**：`xlsx`（高）、`tencent-docs-sheet-generation`（高）
- **判定**：两者都能做——前者覆盖"从图片/数据生成工作簿"的通用路径，后者面向从零生成新表。
- **动作**：**询问**（归入 B 类），不是直调。
- **要点**：直调的前提是"高置信度 **且唯一**"。只要存在第二个同等胜任的候选，就必须先问——两条路径的产出结构会不同。

### A3
- **输入**：「这段剧本文本做成动态漫剧」
- **候选**：`script-to-manhua-drama`（高）
- **理由**：任务产出物（AI 漫剧）与该技能描述逐字对应。
- **动作**：直接调用
- **输出**：`用 script-to-manhua-drama 处理：剧本转漫剧是它的核心流程。`

### A4
- **输入**：「把这个 CSV 画成几个交互式图表」
- **候选**：`smart-charts`（高）、`xlsx`（中）
- **判定**：产出物是"交互式 HTML 图表"，`smart-charts` 的产出物完全一致；`xlsx` 侧重表格处理，图表非其产出物类型。
- **动作**：直接调用 `smart-charts`
- **输出**：`用 smart-charts 处理：它直接把数据文件转成独立交互式图表。`

## B. 需要确认（多候选 / 改变执行方式）

### B1
- **输入**：「帮我写一份 Q3 复盘，要有图表」
- **候选**：`tencent-docx`（高，Word 交付）、`tencent-pptx`（高，汇报交付）、`smart-charts`（中，图表部分）
- **为何要问**：交付物形态（Word / PPT）会彻底改变排版与内容组织方式，无法从输入推断。
- **动作**：列 3 个候选 + 说明差异，等用户选
- **输出**（示意）：
  ```markdown
  这几条路差别不小，先定一下（回字母即可）：

  **1. tencent-docx** — 生成排版规范的 Word 复盘文档
     匹配理由：任务要"复盘"，Word 是标准的书面复盘载体
  **2. tencent-pptx** — 生成可汇报的演示文稿
     匹配理由：若复盘用于会议汇报，PPT 更合适
  **3. smart-charts** — 把数据转成交互式图表页
     匹配理由：任务点名要图表，它专门负责图表产出

  > 也可以直接说"按你的判断"，我选 1 并标出假设。
  ```

### B2
- **输入**：「看看这个网页上的数据，整理给我」
- **候选**：`web-access`（高）、`browser-use`（高）
- **为何要问**：静态抓取与真实浏览器操作在能力、耗时、稳定性上差异明显；若页面需登录或动态渲染，只有后者可行。
- **动作**：询问，且问题应聚焦"页面是否需要登录/动态渲染"
- **注意**：不要为了凑数把 `agent-browser`、`playwright-cli` 一起列出——同一能力面只保留最优候选。

## C. 静默执行（需要技能，但相关度不足，调用不划算）

### C1
- **输入**：「把这段文字里的错别字改一下」
- **候选**：`minimax-docx`（中，但仅当输入是 .docx 文件时）
- **判定**：纯文本校对，任何技能都不是必经路径；调用只会增加开销。
- **动作**：**静默执行**——不调用任何技能，也不提"没找到技能"
- **输出**：（无匹配说明，直接给结果）

### C2
- **输入**：「整理一下这份访谈记录的文字稿」
- **候选**：`tencent-docx`（中——它做正式文档生成，而这里只是整理文字）
- **判定**：产出物是"整理好的文字"，不是排版文档。中档候选，直调收益不明显。
- **动作**：静默执行，不调用
- **要点**：中档候选的正确归宿是"静默"，**不是**"询问"——询问会平白打断用户。

## D. 未命中（需一句话说明）

### D1
- **输入**：「把这个 .psd 文件按图层导出成 PNG」
- **候选**：`buddy-image-processing`（低——它做修图/去水印/抠图，不做 PSD 图层导出）
- **判定**：低档被丢弃后剩余 0 个，而任务确实需要专科技能（PSD 解析）。
- **动作**：不调用，说明未命中后正常执行
- **输出**：`现有技能里没有对口的，我直接做。`
- **要点**：不要说"我扫描了 40 个技能，都不匹配"。

### D2
- **输入**：「帮我把这段录音转成带时间轴的字幕文件」
- **候选**：`yt-dlp`（低——它下载音视频，不做语音转写）
- **动作**：一句话未命中 + 执行
- **输出**：`现有技能里没有对口的，我直接做。`

## E. 跳过匹配（快速通道，全程静默）

| 输入 | 理由 | 动作 |
|---|---|---|
| 「你好」/「谢谢」 | 闲聊 | 直接回应，不提匹配 |
| 「现在几点」/「1 美元多少人民币」 | 单点查表 | 直接回答 |
| 「解释一下什么是 CAP 定理」 | 常识问答，任务本身不需要技能 | 直接回答（**静默跳过，不报未命中**） |
| 「用 pdf 技能拆一下这个文件」 | 用户已点名 | 直接调用 `pdf`，不再匹配 |
| 「再往右挪 20px」（承接上一个可视化任务） | 同任务线追问 | 沿用既有上下文 |
| 「别管技能了，你直接写」 | 用户显式豁免 | 本会话不再主动匹配 |

**关键区分**：`跳过`（任务不需要技能）与 `未命中`（任务需要技能但无对口）都可能是"没有可用技能"，但只有后者需要说一句话。判据是**任务本身是否需要专科技能**，而不是"有没有匹配上"。

## F. 边界用例

### F1 — 匹配自身与澄清技能的叠加
- **输入**：（需求模糊的复杂任务）「做个数据分析的东西」
- **处理顺序**：先由本技能完成匹配（可能命中 `smart-charts` / `xlsx`），**再把澄清问题合并到同一条确认消息**中一起问。
- **反例**：先发一条"候选技能列表"，用户选完后再发一条"在动手前确认 3 点"——两轮打断。

### F2 — 跨任务线的重复匹配
- 用户先做「把 A.xlsx 做成图表」（命中 `smart-charts`），完成后新开话题「帮我把 B.pdf 转成 Word」。
- **动作**：任务线已切换 → 重新匹配 → 命中 `pdf` / `tencent-docx`。
- **反例**：因为"本会话已经调用过 smart-charts"就跳过匹配。

### F3 — 用户拒绝推荐
- 用户对候选列表回复「都不用，你直接做」。
- **动作**：立即按原任务执行，本会话内不再对同一任务做匹配。

## 判定口诀

1. 先问**产出物是什么**，再找技能——不看关键词字面重合。
2. 先过滤（丢弃低档），再看剩余数量；**剩余 0 个才是"未命中"**。
3. 直调必须同时满足"高相关"**和**"唯一"**和**"不改变执行方式"。
4. 输出长度只有三档：**确认块**（要问）/ **一句话**（直调、未命中）/ **零输出**（跳过、静默执行）。
5. "任务不需要技能"（跳过）≠"任务需要但没对口"（未命中）。前者静默，后者说一句话。
6. 拿不准就用最少的话问一句；不需要问就闭嘴干活。
