# skill-matcher

> 让 AI 在动手之前，先想清楚该用哪把工具。

一个 WorkBuddy / Claude Code 技能（Skill）：在用户下达任务后、尚未开始执行之前，自动扫描已安装的全部技能，判断相关度，选出最合适的那个——能自动就用，有歧义就问，没对口就闭嘴干活。

## 解决的问题

技能装多了之后会出现两种浪费：

- **漏用** — 明明装了专门处理 PDF 的技能，却手写脚本硬解。
- **噪音** — 每次任务都汇报"我扫描了 40 个技能，发现 3 个相关……"，用户被迫读调度日志。

这个技能把匹配做成一个**安静的前置步骤**：只在结论会改变执行方式时才开口。

## 核心行为

| 情形 | 动作 | 用户会看到 |
|---|---|---|
| 恰好一个高相关技能，且不改变执行方式 | 直接调用 | 一句话说明用了哪个 |
| 多个高分候选 / 会明显改变产出形态 | 先确认 | 候选列表（名称 + 用途 + 匹配理由），≤ 3 个 |
| 只有中等相关候选 | 静默执行 | 什么都不说 |
| 任务需要专科技能但无对口 | 未命中 | 一句话，然后正常执行 |
| 闲聊 / 常识问答 / 用户已点名技能 | 跳过 | 什么都不说 |

关键区别：**"任务不需要技能"（跳过）** 与 **"任务需要技能但没对口"（未命中）** 是两回事——前者静默，后者说一句话。

## 安装

把本目录放进 WorkBuddy 的用户级技能目录：

```bash
# macOS / Linux
git clone https://github.com/teenvision/skill-matcher.git ~/.workbuddy/skills/skill-matcher

# Windows (PowerShell)
git clone https://github.com/teenvision/skill-matcher.git "$env:USERPROFILE\.workbuddy\skills\skill-matcher"
```

或手动：把 `SKILL.md` 与 `references/` 复制到 `~/.workbuddy/skills/skill-matcher/`。

无需重启，技能清单在下次会话生效。

## 设计原则

1. **产出物优先** — 先问"要做出来的东西是什么"，再找技能；不看关键词字面重合。
2. **直调三条件** — 高相关 **且** 唯一 **且** 不改变执行方式，三者缺一不可。
3. **输出只有三档** — 确认块 / 一句话 / 零输出。没有第四种。
4. **取更轻的动作** — 能静默就不说，能直调就不问；只有"猜错会导致返工"才升级为确认。
5. **不重复、不打断** — 同一任务线只匹配一次；用户说"你直接做"就彻底停。

## 边界

本技能是**元技能 / 路由层**，只做"扫描 → 匹配 → 调度"三件事，不执行任何具体业务任务，也不替代被选中技能的内部流程。

与需求澄清类技能（如 `clarify-before-action`）是**先后关系**：本技能先决定"用什么"，澄清技能后判断"需求够不够清楚"。两者需要同时发生时，澄清问题必须合并进同一条消息，避免连开两轮提问。

## 适配与改动

`references/matching-examples.md` 里的用例基于作者本机的技能集。换到你的环境时，建议：

1. 保留"判定口诀"与规则部分，它们与具体技能无关。
2. 把样例里的技能名替换为你实际安装的，作为回归测试集。
3. 新增技能后，补 1–2 条该技能的判定样例，防止边界漂移。
